# Release Maintenance Incidents

This ledger records credential-free release-maintenance incidents and prevention work. It does not authorize provider commerce writes, credential changes, deployment, or retry.

## SCR-2026-08-14-001 — Shopify secret rotation was not fail-safe

**Status:** open at the Production legacy-database preflight gate. PR #15 merged and deployed as `579cc077a6ca4930fbfa88d415b80cc04c12d963`; the fixed preflight returned only `database-denied` before provider dispatch. Rotation acknowledgements were removed and healthy same-revision deployment `d44e6238-0072-4c8c-bbd3-df6929f6164d` is active. The first independent review of the local, uncommitted read-only database-diagnostic source candidate returned HOLD with five P1s; all five were remediated, and fresh independent adversarial review returned GO with no P0/P1 on frozen 29-path manifest `c0a55f38073ca52c138c83635464f168e9245cd7a8c2fc58821ff0a31bf26e28`. The candidate has not been committed, pushed, merged, deployed, or run against Production.

**Trigger:** planned ProductPipeline Shopify credential maintenance exposed that the existing runtime verified inbound Shopify requests with only one client secret and had no fixed, audited way to rotate the one stored Production Shopify access token after a client-secret change.

**Safety outcome:** Shopify app version `productpipeline-read-only-8` (`1090140569601`) was released with exactly `read_products`, `read_orders`, `read_inventory`, and `read_fulfillments`; the merchant approved Update and the signed-in embedded app loaded. Temporary-ack deployment `77c18d72-e757-41be-8692-284d77f2490c` ran the option-free preflight and stopped at `database-denied` before any provider request. The acknowledgement variables were removed; deployment `d44e6238-0072-4c8c-bbd3-df6929f6164d` is Active with one replica and public health at `2026-08-14T20:52:35.738Z` reported `ok`, `shadow-read-only`, external writes false, and historical backfill false. No access-token rotation, Production database write, proposal activation, listing/order/price/inventory write, old-secret revocation, Marketplace Connect change, or Lightspeed effect occurred.

**Containment events:** a cutoff-only Railway change unexpectedly redeployed the prior single-secret release and was immediately rolled back before provider dispatch. A broad Shopify credential-settings accessibility capture then exposed the unused staged secondary. That secondary was revoked and replaced with a fresh clean secondary through value-blind control-plane handling; the clipboard was cleared, and no raw credential is retained in this ledger. Broad credential-page capture is prohibited for the remainder of the incident.

**Failure risks:** changing the primary secret without bounded overlap could reject App Bridge sessions or Shopify webhooks still signed with the oldest unrevoked secret. An ad hoc token exchange could target the wrong shop/app, change scopes, expose a provider error body, mutate the wrong database row, lose unrelated database state, retry an ambiguous credential effect, or persist the one-hour dashboard refresh token into the database/token row.

**Merged prevention foundation:** the runtime now verifies canonical exact-store HS256 session JWTs and webhook HMACs against the current secret plus one distinct optional previous secret for no more than one hour. At cutoff, the previous secret is ignored while current-secret verification remains available. Production and ambiguous environments are environment-only, and token acquisition remains primary-only with bounded redacted transport.

The separate credential administrator pins the exact Production Railway service, Shopify store/app, legacy database, and four canonical read-only scopes. Rotation requires a dedicated expiring single-writer acknowledgement, an active old/new verifier overlap, and at least 15 minutes remaining immediately before the single no-retry provider request. It performs current-token preflight, a complete verified private backup, fresh-token authority verification, full-row compare-and-swap, read-only reopen proof, and final provider verification. It is not imported or mounted by the server and has no provider commerce-write adapter.

**Regression gates:** dual-secret JWT/webhook tests cover current, previous, malformed, duplicate, overlong, exact-cutoff, and post-cutoff behavior. Credential-admin tests cover exact runtime/DB binding, canonical schema and scope authority, wrong shop/app, timeout/redirect/body bounds, no mutation before provider success, backup integrity/permissions, unrelated-state preservation, dispatch-window expiry, forward commit after a verified remote effect, compare-and-swap races, redacted output, refresh-token non-persistence to the database/token row, and the server/provider-write import boundary. The local diagnostic candidate adds adversarial fixed-binding/path, file/link/permission/sidecar, clean WAL-header zero-sidecar behavior, descriptor-bound atomic path substitution, precise open/fstat/close failures, private-memory/read-only/query-only state, exact schema SQL/storage/default/visibility/index/CAS shape, token-blocking CHECK, generated/hidden, STRICT, index collation/order, trigger/foreign-key, integrity, one-row cardinality, no-token-select, no-mutation, direct compiled redaction, absent npm-wrapper argv sentinel, compiled-output, and import-boundary coverage.

**Diagnostic review findings and remediation:** the first frozen candidate was not safe to deploy. A nominal read-only path open could create persistent WAL sidecars; the verified descriptor was closed before SQLite reopened a swappable path; permissive schema checks accepted a CHECK constraint that rejected a fresh token; the supported npm wrapper printed raw argv; and descriptor open/inspect/identity/close failures were mislabeled. The revised local candidate keeps one verified read-only descriptor open, gives SQLite only a bounded private memory snapshot, reruns content/identity/path/sidecar proof after SQLite closes, uses one exact mutation-compatible schema/CAS contract shared with rotation, removes the npm wrapper, and reports separate fixed descriptor lifecycle stages. Fresh independent review confirmed all five remediations plus exact binding, fixed output, runtime isolation, zero network/write/token-value query, source/dist parity, and the full local verification gates. This is reviewed local source evidence, not deployment or Production database proof.

**Current recovery decision:** keep the healthy no-ack same-revision deployment active and stop provider maintenance. Do not generate another dashboard refresh token, edit or restore the database, rerun preflight, request token rotation, revoke the old secret, or remove the previous-secret verifier until the separately reviewed fixed diagnostic identifies the exact local gate and a smallest-boundary reconciliation is approved. The diagnostic can report only fixed credential-free booleans and a stage; it cannot repair state or authorize a later action. At or after any future provider request, rollback remains forbidden and the forward reconciliation procedure applies. This exception expires when the incident closes.

**Open proof:** reviewed source tests and builds do not prove deployment or Production database state. Before closure, require exact committed/merged/deployed identity for the diagnostic, one option-free Production diagnostic result, reviewed reconciliation of only its first failing boundary, fresh release/topology/inbound gates, successful fixed preflight/rotate/verify results, temporary-variable removal, old-secret revocation, new-only inbound verification, and a credential-free incident closure note. Any ambiguous future post-dispatch outcome remains open and must not be retried blindly.
